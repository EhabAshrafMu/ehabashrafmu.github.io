HiveBox

A FastAPI service that turns live readings from public beehive sensors into a hive temperature status, shipped through a gated CI pipeline and deployed to Kubernetes with caching, object storage and metrics.

Swipe to see the whole drawing
Drawing
HB-01 Runtime
Project
HiveBox
Scale
Not to scale
Drawn by
E. Ashraf
  1. Request in. A client calls GET /temperature. NGINX Ingress routes it to the Service, which balances across two FastAPI replicas.
  2. Cache first. The API checks Valkey. A hit returns the cached average straight away; entries live for 5 minutes.
  3. Fetch on a miss. It pulls the latest temperature from three senseBoxes, drops readings older than 7 days, averages the rest and caches the result.
  4. Answer. The response carries the average and a hive status: too cold, good or too hot.
  5. Archive. A background scheduler writes a JSON snapshot to a MinIO S3 bucket every 5 minutes.
  6. Observe. Custom Prometheus metrics (cache hits and misses, current temperature, upstream errors) are scraped by Grafana Agent and sent to Grafana Cloud.

Node.js delivery pipeline on AWS

A private, bastion-protected AWS environment built with modular Terraform, configured with Ansible and deployed by Jenkins, with remote state, a manual approval gate before every apply and an SSH key generated and stored by code.

Swipe to see the whole drawing
Drawing
AW-01 Infrastructure

Node.js on AWS
Scale
Not to scale
Drawn by

  1. Plan, review, apply. A Jenkins pipeline runs Terraform init, format check, validate and plan, then waits for a person to approve before applying. State sits in an encrypted S3 backend with locking.
  2. Network and compute. A reusable network module creates the VPC, public and private subnets, Internet Gateway, NAT Gateway and route tables, then a bastion host and a private app server.
  3. Keys handled by code. Terraform generates a 4096-bit SSH key pair and stores the private key in SSM Parameter Store as a SecureString.
  4. Configure. Ansible reaches the private server through the bastion and installs Docker and Git. The app server only accepts SSH from the bastion's security group.
  5. Deploy. The deploy pipeline jumps through the bastion, ships the code, builds an image tagged with the build number and swaps the running container on port 3000.
  6. Verify and stay private. A final stage confirms the container is running. The app server has no public IP; its outbound traffic leaves through the NAT Gateway.

Two-tier MERN stack with Ansible roles

One playbook that builds a web tier and a database tier on separate Linux hosts from scratch, with reusable roles, group variables and a Vault-encrypted database password.

Swipe to see the whole drawing
Drawing
MN-01 Provisioning
Project
MERN with Ansible
Scale
Not to scale
Drawn by
E. Ashraf
  1. Baseline every host. Play one runs the common role everywhere: full package update, a dedicated mern user and group, and an SSH key for that user.
  2. Build the web tier. Play two installs Node.js, Express, create-react-app and PM2, then renders the app's App.js and CSS from variables in group_vars.
  3. Build the data tier. Play three installs MongoDB, templates mongod.conf, creates the root user from the Vault-encrypted password and switches authentication on.
  4. Serve. PM2 keeps the React app running and listening on all interfaces. Re-running the playbook converges both hosts to the same state.

Built with Ansible roles, group variables, Jinja2 templates, Ansible Vault, MongoDB, Node.js, Express, React, PM2, RHEL
